# Security assessment (candidate)

One page for NPR 7150.2D SWE-135 (static analysis for defects, security, coverage, complexity), SWE-156
(cybersecurity assessment incl. OSS risk) and SWE-159 (test the mitigations), from
[R25](../research/R25-software-assurance-gap.md) F5. Candidate text; the owner confirms it.

## Threat surface

Nyx is a single-site test-campaign tool, run on one workstation or CI runner.

| Surface | Control | Evidence |
| --- | --- | --- |
| Published ports (api, simulator, db, redis, minio) | bound to `127.0.0.1` only in `docker-compose.yml` | `tests/meta/test_compose.py` |
| Operator access | session cookie (itsdangerous), `X-GS-Client` header on every write; identity comes from the cookie, never the body (D-CMD-10) | `tests/integration` api tests |
| Service-to-service Redis | one ACL user per service, least privilege; `scripts/check_acl_log.py` fails CI on any denied command | `tests/integration/test_redis_acl.py`, CI `e2e` job |
| Audit | append-only `audit_log`, written before the action is forwarded | `tests/integration/test_audit_append_only.py` |
| Test controls (`/api/test-controls`, fault injection) | on by default for the local stack (`GS_TEST_CONTROLS=1`), `0` answers 404; never a production feature | D-SIM-12 |
| Secrets | `.env` (git-ignored, generated by `make env`), per-service passwords; none in the repo | `.gitignore`, `tests/unit/test_init_env.py` |
| Operator input in CSV exports | leading `=`, `+`, `-`, `@` neutralised (D-DB-10) | `tests/unit/test_report_csv.py` |

## Checks (run in CI)

| Check | Where | Notes |
| --- | --- | --- |
| ruff `S` (bandit rules) and `C901` (complexity, max 15) | CI `lint`, `uv run ruff check` | every suppression is in `pyproject.toml` (with the reason) or a `# noqa: Sxxx <reason>` on its line |
| `mypy --strict` | CI `lint` | types for defects |
| Branch coverage, gate 80 % | CI `test` | `[tool.coverage.run] branch = true` |
| `pip-audit` on the locked Python dependencies (fails on any known vulnerability) | CI `lint` (needs the network) | local: `uv export --frozen --no-emit-project --no-hashes -o /tmp/req.txt && uv run pip-audit --no-deps --disable-pip -r /tmp/req.txt` |
| `npm audit --audit-level=high` for `ui/` and `e2e/` (fails at high or above) | CI `lint` (needs the network) | local: `cd ui && npm audit --audit-level=high` (same in `e2e/`) |
| SBOM, CycloneDX JSON for the Python lock and both npm locks | workflow `sbom.yml` on `v*` tags, uploaded as an artifact | local: see the workflow steps |
| Pinned versions | exact versions in `pyproject.toml`, `uv.lock`, `package-lock.json`; new releases held 14 days (`[tool.uv]` constraints) | OSS risk control |

## Known gaps (design §4)

- No TLS: the ports are loopback-only, so there is nothing on the wire between hosts. Any network exposure needs TLS first.
- No roles and no second-person approval: any logged-in user may command and run sessions (D-CMD-10).
- Secrets live in `.env`, not in a secret store; MinIO root credentials are used by the archive path.
- No account lockout or password rotation.
- Dependency scans run against known-vulnerability databases only; they do not prove absence of defects. pip-audit
  fails CI on any known vulnerability; npm audit fails at high or critical. A new advisory blocks `lint`
  until the dependency is bumped or the ID is ignored with a written reason (`pip-audit --ignore-vuln ID`).
- The container images (python:3.14-slim, nginx, redis, timescaledb, minio) are neither audited nor in the SBOM.
  They are the largest OSS set under SWE-156.
- The Python SBOM is runtime only (`--no-dev`); the npm SBOMs include dev dependencies and the e2e SBOM is test
  tooling only.
- Test controls are on by default locally: a user of the stack can inject faults. Acceptable on loopback only.

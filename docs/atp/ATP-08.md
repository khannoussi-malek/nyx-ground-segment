# ATP-08: performance
Covers ING-09, ING-10, ALM-05, UI-01, DAT-03. The load driver runs on the machine under test, so state the machine and its load in the report (D-PERF-08).

0. **Quiet machine.** Start at least 10 min after the last `make up` or image build, and only while the 1-min load average is below a third of the cores (4 on the 12-core reference machine): `sysctl -n vm.loadavg` on macOS, `cat /proc/loadavg` on Linux. Each summary records the load before and after. A run that started above it is still reported as measured, never discarded (NCR-01).
1. Run N, 2 vehicles x 10 Hz for 10 min: `make perf`. It writes `docs/perf/run-n-<UTC date>/` (raw CSVs and `summary.md`). Pass lines: ingest p95 < 200 ms (ING-09), alarm p95 < 300 ms (ALM-05), screen p95 < 1 s (UI-01), query p95 < 300 ms (DAT-03).
2. Run P, 2 vehicles x 100 Hz for 5 min: `make perf-p`. It restarts the simulator at `SIM_RATE_HZ=100`, samples the ingest lag every second, writes `docs/perf/run-p-<UTC date>/` (`lag.csv`, `ingest.csv`, `alarm.csv`, `query.csv`, `totals.json`, `summary.md`) and restores 10 Hz. Pass: time lag under 1 s throughout (ING-10); the other figures are informative.
3. Scaling to 10 vehicles x 100 Hz (1000 frames/s): `uv run python -m perf.scaling docs/perf/run-p-<UTC date>` reads that run's `totals.json` and writes `docs/perf/scaling.md`: worker capacity extrapolated from the measured CPU, Redis memory per vehicle-hour, the first bottleneck with the fix from the design, and whether a restarted worker catches up. Read the headroom sentence: it says a restarted worker catches up only when the capacity exceeds the load.
4. Copy the numbers into `docs/atp-report.md` (Gate 5) together with the p95 confidence interval the scripts print.

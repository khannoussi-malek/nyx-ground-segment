# Simplification review: design.md (Gate 2 draft)

Reviewer stance: lazy senior engineer. The question for every decision was "can it go, merge or shrink while every pass condition in spec §4 still passes?" Inputs: spec §4–§5, `docs/design.md` (135 decisions, 31.75 h), `docs/requirements.md`, plus `assumptions.md`, R4, R11 and `design-review-1.md` where a finding touched an earlier fix.

Hard limits respected: nothing on a must-requirement's pass condition is removed, and neither is data-loss protection, hazardous-command safety, the audit log or input validation. No should-requirement loses its pass condition. Where a finding changes how a should is proven, the row says so.

## 1. Summary

**Estimated saving: about 5.65 h, taking the design from 31.75 h to about 26.1 h.** That fits inside the 27 h the spec's gates add up to. The remaining cut list adds about 1.65 h of buffer. The schedule NCR (`NCR-000-schedule.md`) is then probably not needed.

The hour figures use the same granularity as §5.1 and include the tests that D-ENG-14 would require. They are estimates, not measurements.

Three biggest wins:

1. **SR-01: static vehicle ownership with crash-only restart (−1.25 h).** This removes preference, release, live takeover, the `pg_terminate_backend` steal path and in-process Postgres re-locking. Each worker owns one configured vehicle. A crashed worker restarts and replays its own pending entries first. R4 already lists this as option (a0), "Same code as (a2) with the try-lock replaced by config". The design then built takeover, release and steal on top of (a2), and those layers are what this finding removes.
2. **SR-02: delete now the cut-list items that no pass condition needs (−1.0 h).** These are the report sign-off, the ARCHIVE_BACKLOG banner and the FRAMES REJECTED banner. Right now they sit in the estimate and would be built first and then cut.
3. **SR-05: a smaller archiver (−0.75 h).** It replaces the 4-state job machine with one row written after verification, uses one eligibility rule instead of two, and drops the injectable clock. The checksum re-read before delete and the row-count check stay.

### Considered and not proposed

- **API polling Postgres instead of `ui:events`.** Making the database the outbox would need composite resume ids across `alarm_events`, `audit_log` and `tm:*`, which is more code than XADD plus resync. After SR-01 and SR-03, resync is about 5 lines.
- **Crash-only for Redis errors too (D-ING-08).** Docker's restart backoff doubles from 100 ms, so a 15 s Redis outage could push recovery well past the outage. Keep in-process reconnect for Redis and use crash-only only for Postgres (SR-01).
- **Dropping two should-requirements to save time.** Seven shoulds with ≥ 5 required leaves a margin of 2, and cuts 7–8 already spend it.
- **Pub/sub for `ui:events`.** It is the same size as the stream, so there is nothing to gain.

## 3. Looks over-built, but must stay

- **D-SIM-05 (6000-frame ordered producer buffer)**: the only thing that makes ING-01/ENG-02 "0 frames lost" true across a ~15 s Redis outage (RV-10).
- **D-ING-06 `XADD … ACKED` trimming + D-ING-07 `appendfsync always`**: either default loses frames (ING-07, ING-01).
- **D-ING-04 per-frame isolation after a failed batch**: without it, three redeliveries DLQ the poison frame's good batch-mates as well.
- **D-ING-26 30 s reclaim loop**: after SR-01 it is the only actor for ING-08's "idle > 30 s is reclaimed".
- **D-ING-13/17 storage key + event keys**: crash after COMMIT before XACK → no double frame and no double alarm (OPS-4).
- **D-ALM-11 LEVEL events**: hysteresis has memory. Every restart (more of them under SR-01) and every replay (DAT-06) rebuild state from them.
- **D-ALM-14 `alarm_ack_request` (single writer)**: without it ATP-02 ends in RTN_UNACK instead of CLEARED.
- **D-REP-03 live-ACK overlay**: without it replay alarms differ from live when acked yellow escalates (DAT-06).
- **D-ALM-02 10 % deadband on cabin pressure**: the only setting that passes ALM-02 under both readings of "±1 %".
- **D-UI-18 resync**: the crash between COMMIT and the UI publish (RV-05). After SR-03 it costs one message plus the shared snapshot.
- **D-UI-05 age from `t_onboard`**: OPS-3 "no old value is ever shown as current" after a backlog. SR-08 makes it smaller but keeps it.
- **D-CMD-06 `args_hash` confirmation, D-ENG-17 Redis ACL + arg bounds**: hazardous-command safety, so "cannot be sent without both" also holds for curl and for a stray local process.
- **D-CMD-08 grants + triggers + completeness test**: CMD-04 needs both immutability and "every command and ack".
- **D-CMD-11 monotonic `UPDATE … WHERE state IN (…)`**: two writers on command rows. Without it an executed command can end FAILED.
- **D-CMD-04 LATE_VERIFICATION**: Q3 "did the vehicle do it?". It is one row, and it stops a blind resend of `vent_cabin`.
- **D-SIM-07 `pause` and `hold_exec`**: the only way to reach both CMD-02 cases. One fault yields only NOT_RECEIVED.
- **D-DB-10 report freeze into `session_report`**: hot rows are deleted after 25 h, so a report read at the test review a week later must come from the frozen copy. Only sign-off goes (SR-02).
- **D-ARC-03 full re-read + checksum header**: DAT-05's pass condition is literally "checksum re-read matches before delete".
- **D-ENG-16 `CRASH_AT` hooks, `gs-sim backfill`, `HOT_RETENTION_H`**: the only way to run DAT-04/05 and the "three days later" replay deterministically on one day. Only the clock goes (SR-05).
- **D-ALM-12 start fallback to the newest valid `limits_versions`**: one YAML typo plus one crash would otherwise stop ingest for both vehicles.
- **D-ENG-18 single `iso_z()`**: Postgres text output has no `T`/`Z`, and UI-08 covers CSV, reports and logs too.
- **D-PERF-04 `step` fault**: a few lines, and it makes ALM-05's alarm sample cheap to produce.
- **Docs at 2.5 h**: §6 deliverables, and ENG-08 is a must.

# Gate 2 Thin Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fresh clone runs `make up` and shows the two simulated vehicles' live values in the browser through sim → Redis → one ingest worker → TimescaleDB → `ui:events` → SSE → React table, on the final infrastructure (ACL, initdb schema, MinIO, mission db, interface models, CI with coverage gate), with every Gate 2 "proves early" check turned into a test.
**Architecture:** One Python package `gs` (entry points `gs-sim`, `gs-ingest`, `gs-api`, `gs-migrate`) built into one image, run by one compose file that is also the test infrastructure for integration, system and E2E tests. The simulator writes one JSON field `data` per stream entry; the worker stores each batch in one transaction, then publishes `tm` to `ui:events`, then XACKs; the API sends a snapshot then deltas over SSE to a Vite/React console it serves itself.
**Tech Stack:** Python 3.14, uv 0.12.18, FastAPI 0.162.6, pydantic 2.14.3, redis-py 8.1.0, psycopg 3.3.9, Redis 8.10.3, TimescaleDB 2.32.0-pg17, MinIO (bitnamilegacy), React 19.3.1, Vite 8.3.8, TypeScript 6.0.3, Vitest, Playwright 1.65.0, GitHub Actions.
**Spec:** docs/design.md (+ docs/requirements.md)

## Review Focus

1. **First boot on an empty system** — the worker starts before any `tm:<v>` stream exists and the SSE client connects while `ui:events` is absent and `telemetry` has no rows; nothing may crash and the first delta must still arrive (Task 12 `test_stream_missing_at_start`, Task 15 `test_first_boot_empty_stream_and_no_rows`).
2. **Whole-second timestamps** — a `t_onboard` with microsecond 0 must serialize as `.000000Z` everywhere, because the UI drops stale `tm` by string comparison (Task 1 `test_iso_z_sorts_like_time`, Task 8 `test_tm_whole_second_keeps_six_digits`, Task 17 `whole-second timestamps order correctly`).
3. **Redis connection drop under the worker** — the reconnect path (D-ING-03 "after every reconnect") must keep storing with no loss and no duplicate rows (Task 12 `test_survives_redis_connection_kill`).
4. **SSE clients that go away** — a closed tab must end its server loop and release its Redis connection; leaked `XREAD BLOCK` loops would exhaust the API over a test day (Task 15 `test_disconnect_releases_stream`).
5. **Second `make up` on existing volumes** — `.env` and `users.yaml` must stay byte-identical and the DB/demo logins must still work (R2-16 failure mode) (Task 18 `test_up_down_up_keeps_env_and_logins`).
